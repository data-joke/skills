# 交互引导细则：决策点选项模板

主文档「交互引导规范」只定了原则（先征询、带推荐、合并成一次问）；本文件是各决策点的具体选项模板。

## 新增功能区按钮：三个标准决策点，合并成一次征询

图标 / 命名 / 分组位置三项相互独立。流程：**先 `get_ribbon_xml()` 读现状（决策 3 的选项取决于它；全新插件尚未 unpack/init 时没有现状，按「无现有分组」给选项即可）→ 把三项放进同一次 AskUserQuestion 调用**（3 个问题并列，各 3-4 个选项 + ⭐推荐）→ 用户一次答完立即开工。不要拆成「问完图标 → 再问命名 → 再问分组」三轮串行。

**决策 1 — 图标**（选项直接给**具体方案**，不要先问抽象类型再问候选——类型当选项、推荐候选写进描述）：

- 内置图标 ⭐——从 `COMMON_IMAGEMSO` 按功能语义挑（清理类示例：`Clear` / `FormatPainter` / `Spelling`），名单外名字先 `validate_imagemso()` 验证；适用大多数工具型功能
- 字符图标——`draw_icon()` 圆角底+1-2 字（如「清」+主题色）；品牌感/无 API 环境
- AI 生成——提示词按图标规范（见 `ribbon.md`）；需 `check_icon_api()` 通过，未配自动转字符
- 用户提供 PNG——`prepare_icon()` 自动规整 32×32；已有设计稿

**决策 2 — 功能命名**：3 个候选 + ⭐推荐，id/回调名随选定的 label 联动生成：

- label 候选风格：动词短语「清理文本」⭐（动作意图清晰）/ 名词式「文本清理」/ 带前缀「QT·清理」
- 联动规则：`id=btnClean`、`onAction=CleanSelection_Click`（btn+功能名；回调=动宾结构）；tab/group 的 label 同样三选（简洁 ⭐ / 描述性 / 品牌化）

**决策 3 — 分组位置**（选项按读到的现状给）：

- A. 并入现有分组「XXX」⭐（语义同类时优先——功能归并，用户找得到）
- B. 新建分组（组名给 2-3 个候选+⭐）→ 目标 tab：现有自定义 tab ⭐ / 新建 tab（名称三选）/ 内置 tab（如 `TabHome`——注意需 XML 已有 `<tab idMso="TabHome">` 覆盖元素，默认模板没有，见 function-reference 的 `add_group_to_ribbon` 条目）
- C. 跟随用户点名的分组/tab

选了「新建分组」且目标 tab 也有分歧时，tab 选择作为**第 4 个问题**放进同一次调用，不要事后补问。
