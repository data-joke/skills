# 研究规范：信源、搜索与验证

## 关键论断（验证体系的总开关）

**关键论断 = 支撑以下任一项的断言**：TL;DR 结论、机制解释、数字/版本/定价/配额、对比结论、场景推演结论。其余为背景性描述。研究笔记中每条断言必须打 `关键/背景` 标签；独立审查会抽查标签松紧（是否把关键降级为背景以逃避信源要求）。

## 信源分级

| 等级 | 类型 | 使用规则 |
|---|---|---|
| T1 一手 | 官方文档/白皮书、论文、原始数据、法律与标准文本、当事机构或当事人的直接发布（官方博客、源码、财报、会议记录等） | 可单独支撑**"该主体如此声明/发布"**类断言；涉及实际表现、第三方影响、争议事实时，仍需交叉验证或实测佐证 |
| T2 权威二手 | 权威机构研究报告、知名专业团队博客、权威教材、高质量专业媒体 | 关键论断需再有一个独立 T1/T2 佐证 |
| T3 社区 | 论坛问答、自媒体、百科、与主题无利害关系的个人博客 | 只作线索和补充视角，不可单独支撑关键论断 |

补充规则：
- **主体身份优先于载体**：当事人/维护者/原始作者就其本人作品发布的内容（无论博客/论坛帖/社交贴），按 T1 当事方直接发布处理；涉利益冲突时标注立场并找对侧信源
- T1 = 距源头最近，≠ 最可信。财报有粉饰动机、当事方自述是单方立场、官方文档与实际行为可脱节
- **"独立" = 不同原始信息源头（originator）**，而非不同传播主体或渠道。同一新闻稿被多家媒体各自改写、同一主体的多渠道发布，都只算 1 个信源；T2 来源需在笔记中记录其引用的上游来源，两条信源溯源到同一 originator 时计 1 个

## 搜索策略

1. 关键词语言按领域选择：科技/学术领域优先英文检索（覆盖更全、更接近一手），历史/政策/本地实务类话题以中文检索为主，两边互补
2. 直达一手来源：先找该领域权威机构或当事方的官网/官方发布渠道，用当前环境可用的网页抓取/浏览工具直接读原文，再用泛搜索补充；无法打开原文时更换来源，不得用搜索摘要替代证据
3. 涉及具体产品/版本：搜 changelog、release notes、官方定价/配额页
4. 有争议的机制问题：找维护者本人的说法（GitHub issue、官方论坛、作者博客）
5. **强制搜反方**：每个主题必搜批评、局限、失败案例、社区吐槽（GitHub issues、Hacker News、Reddit）——一面倒=没研究完。**可审计要求**：笔记固定记录反方搜索块（≥2 条不同查询词 + 结果概况 + 采纳/不采理由）；确认无反方时写"已搜反方未发现"并附查询词。纯数学/纯概念主题可显式豁免，写明豁免理由
6. **后继探测**：先在笔记写明本次系统当前日期，再对版本化实体（产品/模型/API/框架）搜 "X latest version + 当前年月"；"当前版本号 + 发布日期"必须落到官方 changelog/release notes（T1），禁止以第三方"X 最新版本"文章作唯一依据
7. 时间约束写法：查询词带"YYYY年M月"（或等价时间锚），禁止用裸年份作唯一时间约束
8. 留意搜索结果发布日期：过时信息（如已废弃的 API 行为）比没有信息更糟

**摘要 ≠ 证据**：搜索结果摘要只用于探索定向。支撑论断的记录必须来自打开过的原文，且含四字段：**URL + 访问日期 + 逐字直接引文 + 定位符**（章节名/标题/锚点）。禁止用转述替代引文——编造逐字引文+定位符的难度远高于编造转述，且可被独立审查实际打开 URL 抽验。

## 时效分级（核验窗口）

窗口起算 = 信源发布或最后更新日期（不是搜索当天）。超窗内容视为待验证，重新核验后才能进笔记。未列出领域一律每次重核。

| 领域 | 核验窗口 |
|---|---|
| AI/大模型、区块链 | 3-6 个月 |
| 云服务、前端框架 | 6-12 个月 |
| 编程语言、数据库 | 1-2 年 |
| 政策法规 | 以官方公报/现行有效性为准，每次必核 |
| 医学/临床 | 按指南版本更替 |
| 商业数字 | 按财报/统计周期 |
| 算法原理、设计模式、数学 | 不限 |

## 适用对象（泛化防护）

- 机制表述标注适用对象：哪家产品 × 哪个版本 × 哪档套餐/部署方式
- 不同对象行为不同时，禁止合并成一句泛化陈述
- 区分三层并如实标注：官方文档声明 / 实测与社区报告 / 推测——"文档说"≠"实际是"；两者冲突时并列记录，不擅自裁决

## 时效标注

- 版本敏感内容（行为、数字、版本号、配额）必须标注"截至 YYYY-MM-DD"
- 训练记忆里的机制描述一律视为待验证假设：先在笔记打 `[记忆假设]` 标签，核验通过（T1/T2 命中且语义一致）才可摘标签，未通过不得进正文
- 文档说法与训练记忆冲突时，以文档为准，并留意是否为近期变更

## 确定性档位（五档）

| 档位 | 表述方式 |
|---|---|
| 有源事实 | 直接陈述，来源按 ID 记入笔记 |
| 来源冲突 | 并列"A 说…（T级）/ B 说…（T级）"，标注等级，不裁决；并列≠等权 |
| 严格推断 | "推断：……（依据是笔记条目 #N…）"——依据只能是笔记中已有编号的有源前提，推理链逐步写出；禁止以"领域知识/公认/经验"作依据 |
| 未证实 | "未查到官方说明"——宁缺毋滥 |
| 声明 vs 实测不一 | "官方声明…；实测/社区报告…"分开标注 |

禁止：把推断写成事实；用"一般来说""通常"掩盖无依据。

## 研究笔记模板

小节与子问题一一对应；关键论断逐条编号：

```markdown
本次运行系统日期：YYYY-MM-DD

## <子问题 N>
| ID | 论断（关键/背景） | 确定性档位 | 来源1（T级+URL+日期+逐字引文+定位符） | 来源2 | 冲突说明 |
|---|---|---|---|---|---|
| N1 | … | 有源事实 | … | … | |

### 反方搜索
- 查询词1 / 查询词2 → 结果概况 → 采纳/不采理由（或豁免理由）
```

来自记忆未核验的内容打 `[记忆假设]`，不得进入成文。
