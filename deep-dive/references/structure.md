# 文章骨架

## 体裁判定（第 1 步解构时确定，写入提纲）

| 体裁 | 适用 | 主体骨架 |
|---|---|---|
| 技术深潜（默认） | 机制、系统、工具 | 问题背景 / 原理 / 场景推演 / 对比 |
| 科普解释 | 面向理解的概念、现象 | 现象 / 概念 / 机制 / 例子 / 误区 |
| 决策参考 | 选型、要不要做 | 决策问题 / 约束 / 选项对比 / 推荐及理由 / 风险 |
| 历史/政策 | 事件、沿革、政策分析 | 背景 / 时间线 / 行动者 / 机制 / 争议解释 / 证据局限 |

通用模块（所有体裁必有）：TL;DR / 局限与适用边界 / 参考。层次按需取用、按内容定轻重，紧凑优先；不必每节都等长、都齐全。快速档可精简为：TL;DR / 核心机制 / 局限与边界 / 参考。

## 结构（以默认"技术深潜"为例）

```markdown
# 标题
说清对象+角度。不用悬念式标题，不用"一文读懂"式空话。

## TL;DR
3-5 句，固定信息结构：
①一句话回答主题问题 ②核心机制/原因 ③适用范围+截至时间 ④主要不确定点或行动建议。
读者只读这段也能带走主要东西。

## 1. 问题背景
它为什么存在：没有它时的具体痛点是什么。从问题引出机制，不从定义开始。

## 2. 原理
机制如何运转。拆到"关键变量"层面——是什么决定了它的行为。
用机制语言写，不用营销语言。
机制表述标注适用对象（哪家产品 × 哪个版本/套餐）。

## 3. 场景推演
真实场景逐个推演：条件 → 机制推导 → 结论。
这是检验"真懂"的部分：每个场景结论都必须能从第 2 节的机制推导出来。
场景优先取自研究中的真实案例（issue、官方示例、问答），自拟场景必须可从机制推导。

场景生成用**变量矩阵法**，保证覆盖、避免重复：
- 基准场景 = 该机制最常见的默认用法
- 从第 2 节的关键变量中，逐个"只变这一个"构造对照场景，从机制推导结论
- 两个场景推出相同结论 → 只留一个
- 推导所需机制细节笔记里没有 → 回研究补搜，禁止硬推
（示例——主题"提示词缓存"，取关键变量"模型、上下文前缀、并发"构造对照场景：同一会话切换模型 / 同一模型新建会话 / 同一模型多会话并发，逐个从缓存键构成推导命中与否）

本节只适用于有机制可推导的主题（技术、规则、自然科学类）；历史、人物、政策评述类整节省略，深度由因果链与多方证据承担。

## 4. 对比与联想
- 相邻概念辨析：与最易混淆的 1-3 个概念对比（可用表格：维度 × 概念）——必须保留（无易混对象除外）
- 跨域类比：必须尝试寻找；只保留非牵强、能揭示结构性机制的类比，找不到合适类比时在笔记记录原因后省略，禁止硬凑
  类比点到为止，并说明类比在哪里失效——不说破失效点，类比会误导
  类比只需思想层面对应；类比里出现的具体机制细节要么查证要么删

## 5. 局限与适用边界
适用于谁/哪个版本/哪些条件；不适用于什么；已知代价、失败情形、反例、证据缺口。
反方研究结论落点在此。主题确无明显局限时，也要说明核验范围，不得静默省略。

## 6. 常见误区
2-4 条。每条：错误认知 → 为什么错（机制层面）→ 正确理解。

## 7. 深挖（可选）
≤3 条继续钻研的路径：官方文档哪一节 / 哪处源码 / 可亲手做的验证实验。

## 参考
编号按正文首次引用顺序排列；每条含 T 级 + 访问日期。
正文关键论断带 [n] 编号，与参考列表一一对应——读者可从任一关键论断跳到来源。
```

## 受众假设

对相关领域有一般认知、但非该主题专家的读者。兼顾可发布：术语有解释、铺垫够用，但不迁就零基础。
