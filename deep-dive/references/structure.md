# 文章骨架

层次按需取用、按内容定轻重，紧凑优先。不必每节都等长、都齐全，但【原理】【场景推演】【对比与联想】是深度与联想的直接来源——除非确实不适用于该主题，否则保留。其中【场景推演】只适用于有机制可推导的主题（技术、规则、自然科学类）；历史、人物、政策评述类主题整节省略，深度由因果链与多方证据承担。

## 结构

```markdown
# 标题
说清对象+角度。不用悬念式标题，不用"一文读懂"式空话。

## TL;DR
3-5 句核心结论。读者只读这段也能带走主要东西。

## 1. 问题背景
它为什么存在：没有它时的具体痛点是什么。
从问题引出机制，不从定义开始。

## 2. 原理
机制如何运转。拆到"关键变量"层面——是什么决定了它的行为。
用机制语言写，不用营销语言。
机制表述标注适用对象（哪家产品 × 哪个版本/套餐）。

## 3. 场景推演
真实场景逐个推演：条件 → 机制推导 → 结论。
这是检验"真懂"的部分：每个场景结论都必须能从第 2 节的机制推导出来。
场景优先取自研究中的真实案例（issue、官方示例、问答），自拟场景必须可从机制推导。

场景生成用**变量矩阵法**，保证覆盖、避免重复：

- 基准场景 = 该机制最常见的默认用法
- 从第 2 节的关键变量中，逐个"只变这一个"构造对照场景，从机制推导结论
- 两个场景推出相同结论 → 只留一个
- 推导所需机制细节笔记里没有 → 回研究补搜，禁止硬推

（示例——主题"提示词缓存"，取关键变量"模型、上下文前缀、并发"构造对照场景：同一会话切换模型 / 同一模型新建会话 / 同一模型多会话并发，逐个从缓存键构成推导命中与否）

## 4. 对比与联想
- 相邻概念辨析：与最易混淆的 1-3 个概念对比（可用表格：维度 × 概念）
- 跨域类比：同样的思想在其他领域的复现（操作系统、网络、建筑、管理……）
  类比点到为止，并说明类比在哪里失效——不说破失效点，类比会误导
  类比只需思想层面对应；类比里出现的具体机制细节要么查证要么删

## 5. 常见误区
2-4 条。每条：错误认知 → 为什么错（机制层面）→ 正确理解。

## 6. 深挖（可选）
≤3 条继续钻研的路径：官方文档哪一节 / 哪处源码 / 可亲手做的验证实验。

## 7. 参考
带访问日期的来源列表，T1 在前。
```

## 受众假设

对相关领域有一般认知、但非该主题专家的读者。兼顾可发布：术语有解释、铺垫够用，但不迁就零基础。
