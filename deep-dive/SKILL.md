# 深度研究文章（deep-dive）

给定任意领域的主题/概念，产出**专业、真实、系统、有深度、能联想**的中文研究文章。

其中四项有硬指标：真实 = 关键论断按 ID 可回溯、确定性不升级；系统 = 子问题→笔记→章节有映射；深度 = 机制拆解 + 场景推演；联想 = 相邻概念辨析 + 跨域类比。

核心认识：文章不可靠的根源是"跳过研究、凭训练记忆直接生成"。所以本 skill 的主干是研究流水线，写作只是最后一环。"真实"不能靠态度保证，只能靠机制：每个关键论断可回溯到来源，且产出者 ≠ 审查者。

**存档根目录**：默认 `~/articles/`（用户指定时从其指定）。全文所有"扫描旧文/存档/更新"都指向该根目录，禁止硬编码机器绝对路径。

## 档位：先定档并确认，再开跑

定档优先级：
1. 用户原话含明确档位信号（"快速过一下/简单讲讲"→快速；"深挖/彻底搞懂/全量对比"→深挖）→ 直接定档，**无需再确认**
2. 用户给了篇幅/耗时约束 → 按约束映射档位
3. 无信号 → 默认标准档

**凡属推断（非用户明说）的档位，必须在开工前向用户确认一次**，与第 0 步澄清合并为同一轮交互，格式：

> "本次拟按【标准档】：约 8-15 次搜索，2000-4000 字，含独立审查。回复'改快速/深挖'或'继续'。"

用户确认前不进入研究步骤。档位一经确认，中途不擅自升降级；确需变更时说明原因并再次确认。

| 档 | 触发 | 字数 | 搜索预算 | 写作期回跳补搜上限 | 独立审查 |
|---|---|---|---|---|---|
| 快速 | 用户明说"快速/简单讲讲" | ≤1500 字 | ≤5 次 | ≤1 处 | 跳过（完成报告注明"未经独立审查，不宜直接引用/发布"） |
| 标准 | 默认 | 2000-4000 字 | 8-15 次 | ≤3 处 | 必做 |
| 深挖 | 用户明说"深挖/彻底搞懂" | 4000-6000 字（超上限建议拆系列） | 15-30 次 | ≤5 处 | 必做 |

搜索预算含反方与后继探测；写作期每次补搜计入预算。超预算时向用户报告原因与剩余工作，不静默膨胀。

## 更新模式

用户要求"更新旧文X"时：
1. **定位旧文**：用户给了路径直接用；只给主题时在存档根目录按目录名/标题/slug 匹配；唯一候选→展示路径后继续；多候选→列出日期+标题让用户选；找不到→说明情况并询问是否新建
2. 读旧文的 article.md 与 research-notes.md，只重新核验时效敏感内容（窗口见 research.md），增量修补正文与笔记，不重写全文
3. research-notes.md 缺失或无法支撑正文关键论断时：告知用户并确认是否先重建笔记；**不得只凭旧正文和记忆直接更新事实内容**
4. 修补完成后在笔记尾部追加更新记录：`日期 + 变动论断 ID + 新来源`

## 流程总览

定档确认 → 输入澄清 → 解构主题 → 多源研究 → 交叉验证（研究笔记）→ 成文 → 独立审查 → 自检 → 存档

**进度透明**：在①定档+提纲②研究笔记完成③独立审查完成后，各向用户简报一次（当前阶段/已用搜索 vs 预算/信源数/未决问题/下一步）。遇阻塞、补搜、查不到、信源冲突时单独说明。

### 第 0 步：输入处理与澄清聚焦

- 输入是主题/概念：默认路径
- 输入是一个具体问题：问题本身就是解构起点（如"为什么切换模型缓存就失效"）
- 输入是链接/材料：先读入内容作为一手信源，再解构

仅当满足以下**任一客观条件**才提问（否则声明默认假设后直接开始）：
- 歧义会影响交付物类型、受众、用途、篇幅或格式
- 主题可对应多个对象/版本/地域/时间范围，选错会导致提纲或研究范围大面积失效
- 无法在同一篇文章中用一小节兼容两种理解

提问规则：最多 3 个问题、逐项编号、每项附默认值；用户只需回答要改的项。方向级歧义停等一次；次要歧义声明默认假设后继续，不要求回复。推断档位的确认合并进本轮，一次问完。

### 第 1 步：解构主题

把主题拆成子问题，形成研究提纲。默认维度：

- **是什么**：定义、分类（有哪些子类/同类方案）
- **为什么存在**：解决什么问题，没有它会发生什么
- **如何工作**：机制拆解——不是"怎么用"，是"怎么运转、为什么这样设计"
- **关键变量**：决定行为的参数与条件（如 TTL、缓存键、失效策略）
- **相邻概念**：最易混淆的对比对象
- **常见误区**

同时判定**体裁**（技术深潜/科普解释/决策参考/历史政策，见 structure.md）——体裁决定骨架，写入提纲。

提纲停等规则：快速档展示后继续跑；**标准/深挖档展示提纲并停等一次确认**（"回复编号调整，或回复'继续'"）；用户明确说过"别停/直接跑"则跳过停等。子问题与研究笔记小节一一对应。

### 第 2 步：多源研究

先读 `references/research.md`（信源分级、搜索策略、笔记模板、时效分级、确定性五档）。

- **易变事实**（产品/API 行为、版本、数字、定价、配额、政策、事件）必须联网核验，以权威一手来源为准；稳定机制优先找权威一手来源，纯定义/数学推导可标"推断"并写出推导依据
- 训练记忆里的内容一律先在笔记打 `[记忆假设]` 标签，核验通过（T1/T2 命中且语义一致）才可摘标签；未通过不得进正文
- 支撑论断的摘录必须来自打开过的原文，且含**逐字引文+定位符**（规范见 research.md）
- **强制搜反方**：笔记记录反方搜索块（≥2 条查询词+结果概况+采纳/不采理由；纯数学/纯概念主题可显式豁免并写明理由）
- **后继探测**：先在笔记写明本次系统当前日期，再搜"X latest + 当前年月"；"当前版本"结论必须落到官方 changelog/release notes（T1）
- **并行策略**：独立子问题的搜索可合并成批并行执行（运行环境支持并行工具调用时）；同一子问题的反方搜索与后继探测同批发起；写作期补搜与审查后处置保持串行

### 第 3 步：交叉验证 → 研究笔记

按 research.md 的验证规则与**笔记模板**产出研究笔记：每条关键论断一行，含 ID、关键/背景标签、确定性档位、来源（T级+URL+访问日期+逐字引文+定位符）、冲突说明。关键论断定义与 T1 使用规则见 research.md。

- 关键论断：≥2 个独立信源（独立=不同原始信息源头 originator），或 1 个 T1 且仅限"该主体如此声明/发布"类断言
- 信息冲突：并列呈现各方说法、依据与信源等级——并列≠等权
- 某子问题 ≥2 轮搜索仍无果：两轮必须换策略维度（换语言/换关键词族/直达官网站内/换渠道），笔记记录每轮查询词；仍无果才标"未查到"，对应文章小节缩短，不硬写

研究笔记先于文章存在，是文章**唯一**的事实依据。

### 第 4 步：成文

读 `references/structure.md`（按体裁选骨架）与 `references/style.md`（风格规则）。

- **从研究笔记写，不凭记忆补内容**——笔记里没有的不写；长文按节写作，每节动笔前重读笔记对应小节
- 写作中发现笔记缺口 → 回第 2 步补搜该点 → 更新笔记 → 继续写；**回跳补搜不超过档位上限**，超限即停：判定提纲不合格，向用户报告缺口
- 正文关键论断带引用编号 [n]，与参考列表一一对应（规范见 structure.md）
- 对比与联想：相邻概念辨析必须保留（无易混对象除外）；跨域类比必须尝试寻找，只保留非牵强、能说明失效边界的类比，找不到时在笔记记录原因后省略——**禁止为满足结构硬凑类比**
- 成文前扫一遍存档根目录：按当前主题关键词匹配目录名/标题，最多查前 20 个候选；有强相关旧文就互链一句，未找到则跳过

### 第 5 步：独立审查（快速档跳过）

spawn 独立 sub-agent（fresh context，禁止 fork 或继承本次会话上下文），**只给 `article.md + research-notes.md` + 一张任务卡**（用户问题/受众/档位/体裁），任务是攻击而非润色：

- **全量来源核对**：文中每个关键论断逐条按 ID 回查笔记来源是否真支撑——不做抽样
- **原文回访**：抽 ≥3 条（深挖档 ≥5 条）最关键或最可疑的论断，用笔记里的 URL 重新打开原文，核对逐字引文与定位符真实存在且确实支撑
- 攻击推导链：场景推演的结论真的从机制推得出吗？找推理跳跃、含糊兜底、确定性档位升级
- 结构层面：体裁骨架是否服务主题、TL;DR 与正文是否一致、局限与反方是否缺失

输出问题清单（`编号｜位置｜类型(事实/推导/档位/结构)｜严重度｜建议处置`）。处置：事实级必须修——补搜/降级存疑/删除三选一；事实错误占比 >20% 或核心章节失守 → 判定研究阶段返工，计入回跳上限。修复后复审一轮，最多 2 轮。

### 第 6 步：自检收尾（事实层已由第 5 步把关，自检只管修复引入的新问题与风格层）

- **复查修复处**：改写/补搜的段落有没有把存疑写回事实——修复时最易引入确定性升级
- 反向回溯：笔记中支撑骨架各节的关键内容，都进了文章或显式舍弃了吗？
- 术语首次出现都有通俗解释吗？存疑标注格式全篇统一吗？每个类比都说明失效点了吗？
- 五项产出要求快检：专业（术语有解释、无营销语言）/ 真实（关键论断可按 ID 回溯、档位不升级）/ 系统（子问题→笔记→章节有映射，缺失内容显式舍弃）/ 深度（机制拆到关键变量、场景结论可由机制推导）/ 联想（相邻概念有区分维度、类比说明失效边界）——任一不达标，回到对应步骤修
- 快速档专项（无独立审查）：加查文中数字/版本号是否都有笔记来源
- 删词检查：先按 style.md 词表机械扫描，再逐段通读删不减义的字词

### 第 7 步：存档

每篇文章一个目录，文章与笔记分开存（默认存档根目录，用户指定其他位置时从其指定）：

```
~/articles/<YYYY-MM-DD-主题slug>/
├── article.md         # 成稿
└── research-notes.md  # 研究笔记（含全部来源与更新记录）
```

完成后向用户报告：
1. 文件位置 + 体量（字数、结构一览）
2. 核心结论 3 条——只读报告也能带走
3. 主要信源概览 + 实际搜索次数 vs 预算
4. 独立审查发现的问题及处置（快速档：注明未经独立审查的风险）
5. 存疑/推断清单 + 采用的关键假设
6. 可继续深挖的点（更新模式：附修改段落+原因+对应新来源）

## 失败与降级

- 网络不可用/搜索连续失败：告知用户实际情况；未核验内容全部按"推断/待验证"降级标注后继续，或经用户确认中止——禁止静默跳过核验继续产出
- 单点搜索失败：换查询词重试 ≤2 次后记"未查到"
- 独立审查大面积失守：见第 5 步返工规则
