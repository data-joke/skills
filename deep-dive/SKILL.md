# 深度研究文章（deep-dive）

给定任意领域的主题/概念，产出**专业、真实、系统、有深度、能联想**的中文研究文章。后两者有硬指标：深度 = 机制拆解 + 场景推演，联想 = 相邻概念辨析 + 跨域类比（落点与适用范围见文章骨架）。

核心认识：文章不可靠的根源是"跳过研究、凭训练记忆直接生成"。所以本 skill 的主干是研究流水线，写作只是最后一环。"真实"不能靠态度保证，只能靠机制：每个关键论断可回溯到来源，且产出者 ≠ 审查者。

## 档位

开始前先定档，并告知用户（"本次按标准档，预计约 N 次搜索 / N 分钟"）。档位只影响广度与审查强度，不影响任何真实性规则。

| 档 | 触发 | 预期 | 独立审查 |
|---|---|---|---|
| 快速 | "快速过一下""简单讲讲" | ≤1500 字，只做核心子问题 | 跳过 |
| 标准 | 默认 | 2000-4000 字 | 必做 |
| 深挖 | "深挖""彻底搞懂" | 4000 字以上，子问题全展开 | 必做 |

## 流程总览

输入澄清 → 解构主题 → 多源研究 → 交叉验证（研究笔记）→ 成文 → 独立审查 → 自检 → 存档

### 第 0 步：输入处理与澄清聚焦

- 输入是主题/概念：默认路径
- 输入是一个具体问题：问题本身就是解构起点（如"为什么切换模型缓存就失效"）
- 输入是链接/材料：先读入内容作为一手信源，再解构

- **何时提问**：唯一标准——歧义会不会导致完全不同的文章。会（如"大模型缓存"可指 KV cache / prompt cache / 语义缓存）→ 先确认；不会 → 直接开始，不问
- **怎么问**：所有问题一次问完，每题附默认答案"默认按X写，不回即按此"，用户不回复流程照走

### 第 1 步：解构主题

把主题拆成子问题，形成研究提纲。默认维度：

- **是什么**：定义、分类（有哪些子类/同类方案）
- **为什么存在**：解决什么问题，没有它会发生什么
- **如何工作**：机制拆解——不是"怎么用"，是"怎么运转、为什么这样设计"
- **关键变量**：决定行为的参数与条件（如 TTL、缓存键、失效策略）
- **相邻概念**：最易混淆的对比对象
- **常见误区**

提纲展示给用户后不停下等待，直接进研究；有问题用户会随时打断纠正，多数时候等待只是白耗时间。
子问题与研究笔记小节一一对应：每个子问题在笔记里有同名小节承接，保证都研究到，成文时也好按节回查。

### 第 2 步：多源研究

先读 `references/research.md`（信源分级、搜索策略、时效分级、泛化防护、存疑标注规范）。

- 时效敏感内容（机制、数字、版本、事件、政策、行为）**必须联网核验**，以权威一手来源为准；训练记忆里的内容一律视为待验证假设，不是事实
- **联网失败降级**：网络不可用/搜索连续失败时，告知用户实际情况；未核验内容全部按"推断/待验证"降级标注，或经用户确认后中止，禁止静默跳过核验继续产出
- 支撑论断的摘录必须来自打开过的原文，搜索摘要只用于探索定向
- **强制搜反方**：批评、局限、失败案例——一面倒=没研究完
- **后继探测**：对版本化实体搜"X latest + 当前年月"，确认研究的是当前版本行为
- 每个来源记录：URL、访问日期、关键论断摘录及出处位置

### 第 3 步：交叉验证 → 研究笔记

按 research.md 的验证规则核对，产出研究笔记（markdown，小节与子问题一一对应，含完整来源列表）：

- 关键论断：≥2 个独立信源，或 1 个一手信源
- 信息冲突：并列呈现各方说法与依据，不擅自裁决
- 某子问题 ≥2 轮搜索仍无果：笔记标注"未查到"，对应文章小节缩短，不硬写
- 查不到：明确标注"未查到官方说明"，禁止编造补位

研究笔记先于文章存在，是文章**唯一**的事实依据。

### 第 4 步：成文

读 `references/structure.md`（文章骨架）与 `references/style.md`（风格规则）。

- **从研究笔记写，不凭记忆补内容**——笔记里没有的不写；长文按节写作，每节动笔前重读笔记对应小节
- 写作中发现笔记缺口 → 回到第 2 步补搜该点 → 更新笔记 → 继续写，禁止凭记忆填
- 骨架层次按需取用，紧凑优先，篇幅由内容决定
- 对比与联想层必须有：相邻概念辨析 + 跨域类比（类比只需思想层面对应，其中的具体机制细节要么查证要么删）
- 机制表述带适用对象：哪家产品 × 哪个版本/套餐，不同对象行为不同时禁止合并成泛化陈述
- 成文前扫一遍 `~/articles/`（用户指定过其他存档位置则扫该位置）：有相关旧文就在文中互链一句，避免重复造节

### 第 5 步：独立审查（快速档跳过）

用 Agent 工具新起独立 agent（fresh context，**禁止 fork 或继承本次会话上下文**），**只给 `article.md + research-notes.md`**（不给研究过程，防锚定），任务是攻击而非润色：

- **全量来源核对**：文中每个关键论断，逐条回查笔记来源是否真支撑——不做抽样
- **原文回访**：抽 3 条（深挖档 5 条）最关键或最可疑的论断，用笔记里的 URL 重新打开原文，核实摘录真实存在且确实支撑该论断——防"研究阶段摘录失真"，这是笔记作为唯一事实依据的信任根
- **攻击推导链**：从笔记的机制出发，场景推演的结论真的推得出吗？
- **找推理跳跃、含糊兜底（"一般来说/通常/显著"）、确定性档位升级（笔记是推断/存疑，文中写成事实）**

输出问题清单（条目 + 严重度）。处置：事实级必须修——补搜 / 降级存疑 / 删除三选一；风格级酌情。

### 第 6 步：自检收尾

事实层已由独立审查把关，自检只管修复环节引入的新问题和风格层，逐条快过：

- 复查修复处：改写/补搜的段落有没有引入确定性升级——修复时最易把存疑写回事实
- 反向回溯：笔记中支撑骨架各节的关键内容，都进了文章或显式舍弃了吗？
- 术语首次出现都有通俗解释吗？存疑/推断标注格式全篇统一吗？
- 删词检查：先按 style.md 词表机械扫描，再逐段通读删不减义的字词
- 快速档（无独立审查）：加查文中数字/版本号是否都有笔记来源

### 第 7 步：存档

每篇文章一个目录，文章与笔记分开存（默认 `~/articles/`，用户指定其他位置时从其指定）：

```
~/articles/<YYYY-MM-DD-主题slug>/
├── article.md         # 成稿
└── research-notes.md  # 研究笔记（含全部来源）
```

完成后向用户报告：
1. 文件位置 + 体量（字数、结构一览）
2. 核心结论 3 条——只读报告也能带走
3. 主要信源概览
4. 存疑/推断清单
5. 可继续深挖的点
