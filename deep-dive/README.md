# deep-dive — 深度研究文章 Skill

> 给定任意领域的主题或概念，让 AI agent 走一条**"先研究、后写作、再审查"**的流水线，产出**专业、真实、系统、有深度、能联想**的中文研究文章。

适用于：技术、科学、商业、历史、政策、方法论……任何你想"彻底搞懂并写下来"的主题。任何支持 skill 机制的 agent 均可使用。

```bash
/deep-dive 我想深度了解下ai大模型的缓存机制，帮我写篇文章

# 或自然语言触发
"研究一下X" / "深入讲讲X" / "X是怎么运作的"
```

## 为什么需要

大模型直接"写篇关于 X 的文章"，本质是凭训练记忆生成：机制描述、价格数字、版本行为全是待验证假设，还自带一脸自信——文章不可靠的根源就在这里。

本 skill 把"真实"从态度变成机制，只有三条铁律：

1. **先研究，后写作**——研究笔记先于文章存在，且是文章唯一事实依据，笔记里没有的不写；
2. **每个论断可回溯**——信源分级（一手/权威二手/社区），支撑论断的摘录必须来自打开过的原文；
3. **产出者 ≠ 审查者**——成稿后由一个全新的独立 agent 只凭"文章+笔记"做攻击式审查，防锚定。

## 流程

```mermaid
flowchart LR
    A[输入澄清] --> B[解构主题<br/>研究提纲]
    B --> C[多源联网研究<br/>强制搜反方]
    C --> D[交叉验证<br/>研究笔记]
    D --> E[成文<br/>按骨架与风格规则]
    E --> F[独立审查<br/>fresh agent]
    F --> G[修复+自检]
    G --> H[存档]
```

### 研究阶段的关键动作

| 动作 | 说明 |
|---|---|
| 信源分级 | T1 一手（官方文档/论文/源码）可单独支撑论断；T2 权威二手需佐证；T3 社区只作线索 |
| 强制搜反方 | 每个主题必搜批评、局限、失败案例——一面倒 = 没研究完 |
| 后继探测 | 对版本化实体搜 "X latest + 当前年月"，确认研究的是当前版本行为 |
| 摘要 ≠ 证据 | 搜索摘要只用于定向；支撑论断的摘录必须来自打开过的原文 |
| 时效窗口 | AI/大模型类内容 3-6 个月核验窗口，数字必须标注"截至"日期 |

### 审查阶段

独立 agent 拿到的只有 `article.md + research-notes.md`（不给研究过程，防锚定），任务是**攻击而非润色**：

1. **全量来源核对**——文中每个关键论断逐条回查笔记，不做抽样
2. **原文回访**——抽最关键/最可疑的 3-5 条论断，用笔记里的 URL 重新打开原文核实
3. **攻击推导链**——场景推演的结论从机制真的推得出吗？
4. **找确定性升级**——笔记里是"推断/存疑"，文中是否写成了事实

事实级问题必须修：补搜 / 降级存疑 / 删除，三选一。

## 档位

| 档 | 触发词 | 预期 | 独立审查 |
|---|---|---|---|
| 快速 | "快速过一下" | ≤1500 字，只做核心子问题 | 跳过 |
| 标准 | 默认 | 2000-4000 字 | 必做 |
| 深挖 | "深挖""彻底搞懂" | 4000 字以上，子问题全展开 | 必做 |

## 产物结构

```text
~/articles/<YYYY-MM-DD-主题slug>/
├── article.md         # 成稿
└── research-notes.md  # 研究笔记（含全部来源与访问日期）
```

文章骨架：TL;DR → 问题背景 → 原理（机制拆解，标注适用对象）→ **场景推演**（从机制推导，检验"真懂"）→ **对比与联想**（相邻概念辨析 + 跨域类比，类比必说失效点）→ 常见误区 → 深挖路径 → 参考（带访问日期）。

## 实战案例

**《大模型的三层缓存：KV Cache、Prompt Caching 与语义缓存》**（2026-09-06，深挖档）：

- 20+ 次检索，21 个一手来源（6 家厂商官方文档 + 5 篇 arXiv 论文 + vLLM/GPTCache 官方仓库）
- 独立审查回访 7 个原文页面：数字层零错误，但抓出 **13 个事实级问题**——包括 2 处引用失实、1 处 TL;DR 数值归属错误、3 个会误导读者实际操作的错误结论，全部修复后才交付
- 审查的价值正在于此：写作时的"我以为"和原文之间，永远存在偏差

## 安装

无需手动操作——把下面这段提示词发给你正在使用的 agent，由它自行完成安装：

```text
请为当前环境安装 deep-dive skill：
1. 克隆仓库 https://github.com/data-joke/skills.git 到临时目录；
2. 把其中的 deep-dive/ 目录完整复制到你加载 skill 的目录，
   目录名保持 deep-dive（与 SKILL.md 的 name 字段一致）；
3. 完成后报告安装位置，并确认你能读取到其中的 SKILL.md。
```

依赖：agent 具备联网检索与网页抓取能力（如 WebSearch/WebFetch 或等效工具）。联网失败时 skill 会降级标注"待验证"并告知，不会静默跳过核验继续产出。

## 文件说明

```text
deep-dive/
├── SKILL.md                  # skill 主指令（流程、档位、真实性规则）
├── README.md                 # 本文件
└── references/
    ├── research.md           # 研究规范：信源分级、搜索策略、时效与存疑标注
    ├── structure.md          # 文章骨架：各节定位与场景推演的变量矩阵法
    └── style.md              # 风格规则：术语解释、删词表、数字参照系、真实性表达
```

## 设计原则

1. **机制优先**：不是"怎么用"，是"怎么运转、为什么这样设计"；机制表述必须标注适用对象（哪家产品 × 哪个版本）
2. **三档确定性**：有来源 → 直接陈述；无来源可推理 → 明写"推断：…（依据：…）"；查不到 → 明写"未查到官方说明"。禁止把推断写成事实，禁止用"一般来说"掩盖无依据
3. **深度与联想有硬指标**：深度 = 机制拆解 + 场景推演；联想 = 相邻概念辨析 + 跨域类比（且要说明类比在哪里失效）
4. **停不下来就问，问完就走**：只有歧义会导致完全不同的文章时才向用户提问；提纲展示后不停等确认，直接进研究
